# V5.11.30 — Engine Batch

This release turns the Vinted identity experiments into the normal engine while intentionally leaving the visual/UX redesign for the next phase.

## Vinted identity

- Production zero-network batch linker from persistent catalogue snapshots.
- Strong-match-only policy with exact observed price, semantic title evidence, non-game/collision/context safety gates and a wide margin over the second candidate.
- Global one-to-one item-ID assignment.
- Ambiguous rows are not guessed; they remain available to the existing resolver.
- Fresh catalogue snapshots are consumed immediately for sibling observations.

## Queue priority

- LIVE deals, Hunts and manual actions hard-preempt backlog work.
- The backlog does not spend the next public-page permit while urgent work exists but is briefly waiting for pacing/retry time.
- Publication-time/item-page completeness remains a low-priority lane.

## BGG identity / variants

- Batch Vinted identity no longer silently implies that the existing BGG match is exact.
- Newly batch-linked listings enter a temporary variant-pending state.
- Richer public item title/description can reconcile a more specific BGG entry locally (e.g. Tokaido → Tokaido Duo).
- Only the affected listing is moved. Multiple plausible variants are sent to review.
- Market benchmarks exclude variant-pending/review listings until the exact game identity is confirmed.

## Price freshness

- Exact item-page price can refresh the current Ludo price.
- Original scroll observations remain in price history.
- Stale buyer-protection/derived totals are cleared or recomputed when the asking price changes.

## Stability

- Batch pass capped at 180 observations.
- Only one game-family snapshot is decoded at a time to reduce heap pressure.
- Snapshot diagnostics use aggregate SQL instead of decoding all payloads.

## Cleanup

- Removed Settings actions for the controlled batch test and Test 2b one-shot.
- Production diagnostics use engine names rather than shadow-test names.
