# 5.12.1 — Motore as a run, not a dashboard

This iteration replaces the first UX Phase 1 card grid with a run-oriented model.

The top-level Motore screen answers four questions in order: what did the last scroll find, is Ludo still working, how many cards are ready, and does anything need human review. Technical queues remain implementation details.

History is daily-first. A day can be opened to inspect its individual scrolls; a scroll can be opened to inspect only the listings observed in that run.

A one-time safe reset removes the legacy incomplete backlog from active UX while preserving completed records and archiving incomplete ones for possible recovery/re-observation.

A completion notification tells the user when automatic processing has settled and a new scroll can begin.
